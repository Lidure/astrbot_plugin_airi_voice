# Airi Voice 播放器与网页视觉优化设计

## 目标

在 AstrBot Plugin Pages 内提供可操作的语音试听播放器，并优化页面视觉层次、响应式布局和交互反馈。

## 已确认需求

- 试听区域使用单一、持久的页面播放器。
- 支持播放、暂停、进度拖动、音量控制和播放时长显示。
- 点击另一条语音时，当前播放立即暂停并释放旧音频资源。
- 播放器仅在选择语音后显示，并展示当前语音名称。
- 保持现有 bridge API 和音频响应格式，不新增后端接口。
- 页面采用清爽、可爱、粉蓝系视觉风格，避免引入外部依赖。
- 桌面端保持表格浏览，移动端优化为易读的卡片式操作布局。
- 保留加载中、空列表、错误提示、上传、删除和重载功能。

## 方案

### 播放器

HTML 增加播放器卡片，内部使用一个 `<audio controls preload="metadata">` 元素。前端维护当前对象 URL 和当前条目；获取音频数据后设置 `audio.src` 并调用 `play()`。切换条目、播放结束、播放错误和页面卸载时释放对象 URL。由于播放器只有一个实例，浏览器会天然保证不会同时播放多个音频。

### 视觉与布局

使用现有 CSS 变量体系扩展粉蓝强调色、渐变背景、卡片层次、播放器状态和按钮状态。列表操作保持现有功能入口，但增强间距、悬浮反馈、来源标签和小屏幕布局；不引入框架、字体或 CDN 资源。

### 错误处理

音频获取失败时播放器保持隐藏或回到空闲状态，页面错误提示显示 bridge/API 返回的消息。播放新音频前先暂停并清理旧对象 URL，避免内存泄漏和旧音频继续播放。

## 验收标准

1. 点击试听后显示播放器并自动播放目标语音。
2. 点击暂停后声音停止，再点击播放可以继续。
3. 拖动进度条可以跳转到音频指定位置。
4. 点击另一条试听时，上一条停止，播放器切换到新语音。
5. 播放结束后对象 URL 被释放，播放器状态正确。
6. 页面在桌面和窄屏下均可使用，现有搜索、筛选、上传、删除和重载功能不回归。
7. 不增加新的 Python 依赖或独立服务。
