# Airi Voice WebUI 管理 MVP 设计

## 背景

Airi Voice 当前已经支持通过配置页上传语音、通过聊天命令管理语音，以及根据文件名触发语音。但小白用户仍需要理解文件目录、关键词命名和多个管理命令。插件代码中也同时存在普通关键词、随机语音、配置热更新和 LLM 工具等逻辑，因此网页管理功能必须保持兼容并避免改变现有触发行为。

本设计只覆盖第一版 WebUI 管理 MVP，不包含标签、别名、权重随机、统计和 LLM 管理。

## 目标

- 在 AstrBot Dashboard 中提供 Airi Voice 专属管理页面。
- 支持查看、搜索、试听、上传、删除和重载语音。
- 保持现有 `voices/`、`user_added/`、`extra_voices/` 目录和文件名关键词规则兼容。
- 旧版 AstrBot 不支持 Plugin Pages 时，现有聊天命令和配置页仍可使用。
- 上传、删除和重载操作必须受到管理员权限保护。
- 不新增独立 Web 服务、端口或数据库依赖。

## 非目标

- 本阶段不引入 SQLite 或其他数据库。
- 本阶段不改变普通关键词、`随机语音` 和 `/随机关键词` 的现有触发语义。
- 本阶段不实现关键词别名、标签、权重、群组独立配置和使用统计。
- 本阶段不提供独立于 AstrBot Dashboard 的登录系统。

## 用户体验

页面包含以下区域：

1. 顶部摘要：语音总数、可用数量、异常数量。
2. 工具栏：关键词搜索、来源筛选、刷新语音库、上传语音。
3. 语音列表：关键词、来源、格式、大小、试听按钮和删除按钮。
4. 上传面板：选择音频文件、输入关键词、确认上传。

上传时默认使用文件名（去掉扩展名）作为关键词，但用户可以修改关键词。重复关键词默认拒绝覆盖并提示用户。内置 `voices/` 文件只允许试听，用户添加和网页上传的文件才允许删除。

页面需要提供清晰的空状态和错误状态，例如“当前没有可用语音”“关键词已存在”“文件格式不支持”和“权限不足”。网页管理不可用时，帮助文档继续提供现有聊天命令作为替代方案。

## 兼容性策略

AstrBot 支持 Plugin Pages 时，插件注册并提供自定义页面和后端路由。能力不可用或注册失败时，插件不得因此加载失败，只记录警告并保留现有配置页、聊天命令和关键词触发功能。

实现时不立即提高插件的最低 AstrBot 版本要求。应在 `metadata.yaml` 或 README 中说明：网页管理需要支持 Plugin Pages 的 AstrBot 版本，旧版本继续使用基础功能。

## 数据与目录

运行时继续使用现有 `voice_map: Dict[str, str]`，不改变普通触发逻辑。网页接口返回统一的语音条目结构：

```json
{
  "id": "user_added:打卡啦摩托",
  "name": "打卡啦摩托",
  "source": "user_added",
  "extension": ".mp3",
  "size": 183421,
  "available": true
}
```

目录来源定义如下：

- `voices/`：插件内置语音，允许试听，不允许网页删除。
- `data/.../user_added/`：通过聊天命令添加的语音，允许网页删除。
- `data/.../extra_voices/`：网页上传语音，允许网页删除。

每次上传、删除或重载后调用统一的语音库刷新逻辑，重建 `voice_map` 和排序关键词列表。配置池变化检测不能只依赖列表长度，应比较完整内容或使用配置签名，避免同数量文件替换时不刷新。

## 后端接口

具体路由前缀应遵循 AstrBot Plugin Pages 的当前 API 约定，逻辑接口如下：

```text
GET    /voices
GET    /voices/{id}/audio
POST   /voices/upload
DELETE /voices/{id}
POST   /voices/reload
```

接口要求：

- 列表接口支持关键词搜索和来源筛选，默认只返回可识别的音频条目，同时标记缺失文件。
- 试听接口只允许访问三类受控语音目录中的文件，禁止根据用户提交的任意路径读取文件。
- 上传接口只接受 `.mp3`、`.wav`、`.ogg`、`.silk`、`.amr`，首版单文件上限为 20 MB。
- 上传关键词必须非空，拒绝 `/`、反斜杠、`..` 和控制字符。
- 删除接口只接受服务器生成或校验过的条目 ID，不接受任意文件路径。
- 上传、删除和重载接口必须检查插件管理员权限；列表和试听可按 AstrBot Dashboard 的登录权限访问。
- 所有路径使用 `resolve()` 后验证仍位于允许目录内。
- 返回结构包含明确的成功状态、错误代码和用户可读消息。

## 安全与错误处理

- 不启动独立端口，不自行实现登录认证。
- 上传时校验扩展名、文件大小和最终保存路径；必要时保留临时文件并在失败时清理。
- 删除操作前端二次确认，后端再次验证目录和条目来源。
- 重复关键词默认拒绝覆盖，避免误删或覆盖已有语音。
- 文件缺失、音频不可读、非法路径、权限不足和刷新失败都必须返回可理解的错误。
- 不把服务器绝对路径返回给前端，只返回来源、文件名、格式和大小等必要信息。

## 文件边界

预计新增或修改的职责边界如下，具体文件名以 AstrBot Plugin Pages 实际 API 为准：

- `main.py`：保留插件生命周期、权限调用和现有触发入口；调用语音库管理服务。
- `voice_catalog.py`：集中负责扫描、列表、路径验证、上传、删除和刷新。
- `web_api.py`：提供 WebUI 路由、请求校验和 JSON 响应。
- `pages/`：Plugin Pages 前端页面及静态资源。
- `_conf_schema.json`：补充网页管理和兼容性说明，不把文件管理逻辑塞进配置 schema。
- `README.md`、`CHANGELOG.md`、`metadata.yaml`：更新使用说明、版本和兼容性说明。

如果 AstrBot 当前版本的 Plugin Pages API 不适合拆分 `web_api.py`，可以先在 `main.py` 中实现最小适配层，但语音文件操作仍应抽成独立方法，避免继续扩大命令处理器。

## 测试策略

自动化测试优先覆盖不依赖真实音频内容的逻辑：

- 路径是否位于允许目录。
- 扩展名和关键词校验。
- 重复关键词拒绝。
- 内置文件不可删除。
- 列表搜索和来源筛选。
- 配置刷新签名在增删改时变化。
- 普通关键词、随机语音和随机前缀的解析回归。

由于测试环境可能缺少完整语音文件和 AstrBot Dashboard 运行环境，以下内容由用户手动验收：

- Dashboard 页面实际打开。
- 浏览器上传、试听和删除。
- 深色模式和窄屏布局。
- 旧 AstrBot 版本降级后现有命令仍可用。

触发回归矩阵必须包含：

| 配置 | 输入 | 预期 |
| --- | --- | --- |
| 前缀关闭 | 普通关键词 | 触发 |
| 前缀开启 | 普通关键词 | 触发 |
| 前缀开启 | `随机语音` | 触发 |
| 前缀开启 | `随机猫` | 不触发 |
| 前缀开启 | `/随机猫` | 触发 |
| 前缀开启 | `//随机猫` | 不触发 |

## 版本与发布

网页管理 MVP 使用 `v2.8.0`。发布前同步更新：

- `metadata.yaml` 的版本。
- `@register` 的版本。
- README 版本徽章和使用说明。
- CHANGELOG 的新增功能、兼容性和降级说明。

Bug 修复使用 `v2.8.1`，破坏旧配置或命令行为的版本才考虑主版本升级。

发布前至少执行：

```powershell
python -m py_compile main.py
python -c "import json; json.load(open('_conf_schema.json', encoding='utf-8'))"
git diff --check
```

## 实施顺序

1. 先抽取并测试语音库扫描、路径验证和刷新逻辑。
2. 注册兼容性 WebUI 页面和最小后端路由。
3. 完成列表、搜索、试听、上传、删除和重载页面。
4. 增加错误提示、权限检查和旧版本降级。
5. 更新 README、CHANGELOG、metadata 和版本号。
6. 执行自动化检查，并由用户手动验收页面功能。
